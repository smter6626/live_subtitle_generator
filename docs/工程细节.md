# 工程细节

本文档面向开发者和未来维护者，记录当前实时课堂转写项目的工程实现。普通用户说明见 `README.md`。

## 1. 项目整体架构

当前项目的主用户路径是 PySide6 桌面 UI：

```text
ui_app.py
  -> TranscriptionController
  -> TranscriptionEngine
  -> WhisperCppBackend
  -> TranscriptStore
```

运行时主链路：

```text
麦克风输入
-> 48kHz mono capture
-> ring buffer
-> 10s chunk / 3s overlap
-> 16kHz resample
-> whisper.cpp CLI + Metal
-> raw lines
-> simple_dedup()
-> fuzzy_boundary_dedup()
-> clean lines
-> UI tables + session files
```

UI 主线程只负责 Qt 窗口、按钮、表格和事件展示。录音采集和转写在后台线程中进行，避免窗口卡死。

## 3. 转写主链路

`TranscriptionController.start()` 接收 UI 传入的 Beam Size、Original Language、当前模型路径和模型名，构造 `TranscriptionSettings`，校验 runtime path，创建 `TranscriptStore`，然后启动 `TranscriptionEngine`。

`TranscriptionEngine.start()` 启动两个后台线程：

- `audio-capture`：打开 `sounddevice.InputStream`，持续把音频写入 ring buffer。
- `transcription-worker`：从 queue 中取 chunk，调用 whisper.cpp 后端，写 raw/clean。

事件通过 `event_callback` 回到 UI。`ui_app.py` 用 `EventBridge(QObject)` 将 Python 回调转换为 Qt signal，从而在 UI 线程更新表格和日志。

## 4. 音频采集与 chunk 调度

核心音频参数来自 `stream_transcribe.py`：

```text
CAPTURE_RATE = 48000
TRANSCRIBE_RATE = 16000
CHANNELS = 1
BLOCK_SECONDS = 10
OVERLAP_SECONDS = 3
STEP_SECONDS = 7
RING_BUFFER_SECONDS = 30
```

采集逻辑：

- `sounddevice.InputStream(... dtype="float32")`
- callback 中取 `indata[:, 0]` 作为 mono
- 追加到 `deque(maxlen=RING_BUFFER_SECONDS * CAPTURE_RATE)`
- 通过 `total_audio_seconds += frames / CAPTURE_RATE` 维护累计音频时间

chunk 调度：

- 首个 chunk 从 `0.0s` 开始
- 后续 chunk 起点是 `last_chunk_start + STEP_SECONDS`
- 每个常规 chunk 长度是 `BLOCK_SECONDS`
- 当 ring buffer 中可覆盖 `[candidate_start, candidate_end]` 时提交 queue
- 如果候选起点已经落出 ring buffer，会根据 drift 情况记录 warning 并尝试 realign

Stop drain：

- 点击 Stop 后先设置 `stop_event`，采集线程退出，麦克风 stream 关闭
- 调用 `_submit_final_partial_chunk()`
- final partial chunk 范围为 `last_chunk_start + STEP_SECONDS` 到 `total_audio_seconds`
- final partial 最小时长 `FINAL_PARTIAL_MIN_SECONDS = 2.0`
- final partial 最小 RMS `FINAL_PARTIAL_MIN_RMS = 0.0015`
- 过短或能量过低会跳过并记录 log
- queue 中已有任务不会清空，worker 处理完后写入 `Stop complete.`

## 5. whisper.cpp + Metal 后端

UI 主路径使用 `WhisperCppBackend`。后端定义在 `stream_transcribe.py`，UI 侧通过 `TranscriptionEngine` 注入路径、模型、beam、语言。

每个 chunk 的后端处理：

1. 把 16kHz mono float32 numpy array 写成临时 PCM16 WAV。
2. 构造 `whisper-cli` 命令。
3. 使用 `subprocess.run(... capture_output=True, timeout=...)` 调用 CLI。
4. 合并 stdout/stderr，解析 timestamp 行。
5. 输出统一格式：

```text
[start.xx s -> end.xx s] text
```

命令构造要点：

- 固定 `task = transcribe`
- `English` -> `-l en`
- `Chinese` -> `-l zh`
- `Mixed Chinese/English` -> `-l auto`
- Beam Size -> `-bs <beam>`
- 不传 `-tr`
- 不传 `--translate`
- 当前不传 `--prompt`

打包版通过 `resource_paths.py` 找到内置：

```text
ClassroomTranscriber.app/Contents/Resources/bin/whisper-cli
```

源码模式默认使用：

```text
external/whisper.cpp/build/bin/whisper-cli
```

因此全新 Clone 后虽然模型下载脚本可用，源码模式要真正转写仍必须另行准备
`external/whisper.cpp` 的 CLI 后端。模型文件不内置在 app 中，由 Model Manager 管理。

## 6. 模型管理实现

模型管理代码在 `model_manager.py` 和 `ui_app.py` 的 `ModelManagerDialog` 中。

识别规则：

```text
ggml-large-v3.bin       -> large-v3
ggml-large-v3-turbo.bin -> large-v3-turbo
ggml-medium.en.bin      -> medium.en
ggml-small.en.bin       -> small.en
ggml-base.en.bin        -> base.en
其他 ggml-*.bin / *.gguf -> Custom Model
```

默认下载目录：

```text
~/Documents/ClassroomTranscriber/models
```

扫描目录：

```text
当前 download_model_dir
~/Documents/ClassroomTranscriber/models
~/Library/Application Support/ClassroomTranscriber/models
项目目录 models/
external/whisper.cpp/models/
```

路径使用 `_path_key()` / `dedupe_paths()` 去重，避免同一模型重复显示。

`AppSettings` 当前字段：

```json
{
  "whisper_cpp_cli": ".../whisper-cli",
  "selected_model_path": ".../ggml-large-v3.bin",
  "selected_model_name": "large-v3",
  "default_beam_size": 5,
  "download_model_dir": "~/Documents/ClassroomTranscriber/models",
  "model_dirs": [],
  "imported_model_paths": []
}
```

目录创建：

- `ensure_model_dir(path)` 使用 `mkdir(parents=True, exist_ok=True)`
- 检查目标不能是普通文件
- 通过写入临时 probe 文件检查可写性
- 失败时返回 `Cannot create model download directory: <path>`

下载模型：

- UI 点击 `Download Model` 后先确保下载目录存在且可写
- 源码模式调用随主仓库 Vendored 的 `vendor/whisper.cpp/download-ggml-model.sh`
- 脚本锁定自 `ggml-org/whisper.cpp` 提交
  `8443cf05e3fa8ce1b32348e1bcbcf8fc31f7f3ae`，许可证和更新方法记录在同目录
- 全新 Clone 的模型下载不依赖被忽略的 `external/whisper.cpp`
- 当前命令格式：

```bash
sh download-ggml-model.sh <model-name> <download_model_dir>
```

如果目标模型已存在于当前下载目录，会提示 `Model already exists.`，不会重复下载。

导入模型：

- `Import Existing Model` 选择 `.bin` 或 `.gguf`
- 校验存在、是文件、扩展名合法、大小大于 `MIN_MODEL_FILE_SIZE_BYTES`
- 第一版是 use in place，不默认复制 2.9GB 文件

## 8. raw / clean 输出机制

`TranscriptStore` 为每次 session 创建：

```text
raw.txt
clean.txt
session.log
config.json
```

`append_raw()` 和 `append_clean()` 都使用 line-buffered 文件并显式 flush。`close()` 是幂等的。

raw 写入策略：

- 只要后端返回合法行，就写入 raw
- raw 尽量保存原始识别证据

clean 写入策略：

- 将当前 chunk 的 raw lines 合并
- 先经过 `simple_dedup()`
- 再经过 `fuzzy_boundary_dedup()`
- 再做 clean-only hallucination denylist 过滤
- 如果 clean 为空，记录原因但不写空行

clean-only denylist 当前包括：

```text
中文字幕由 Amara.org 社群提供
请订阅我的频道
请点赞
点赞 订阅 转发
```

取舍：raw 保留证据，clean 更适合课堂实时阅读。

## 9. simple_dedup 实现说明

`simple_dedup(new_text, old_text)` 位于 `stream_transcribe.py`。

定位：

- 处理重叠 chunk 导致的精确或标准化边界重复
- 只对 old tail 和 new head 做比较
- 不做全文级 dedup

核心步骤：

1. `tokenize_for_compare(... skip_timestamps=True)` 提取比较 token。
2. `normalize_for_compare()` 小写、去标点、压缩空白。
3. `expand_common_contractions_for_compare()` 将常见 contraction 展开用于比较。
4. `find_overlap_and_cut_index()` 找最长可靠前后缀重叠。
5. 如果 overlap 可靠，裁剪 new_text 前缀。
6. `_preserve_line_timestamp()` 尽量保留 timestamp。

重要点：

- contraction expansion 只影响比较层，不改写输出文本。
- timestamp tag 不参与 token 比较。
- 最少匹配由 `OVERLAP_MIN_WORDS` 和 `OVERLAP_MIN_CHARS` 控制。

## 10. fuzzy_boundary_dedup 实现说明

`fuzzy_boundary_dedup(old_text, new_text)` 位于 `stream_transcribe.py`。

定位：

- 处理边界处轻微改写、口语变化、contraction 变化导致的非完全重复
- 策略保守，避免误删真实课堂内容

比较窗口：

- old tail：最近 `FUZZY_WINDOW_WORDS`
- new head：前 `FUZZY_WINDOW_WORDS`
- prefix 长度范围：`FUZZY_MIN_PREFIX_WORDS` 到 `FUZZY_MAX_PREFIX_WORDS`

判定指标：

- 编辑相似度
- bigram overlap
- 内容词 overlap
- shared content words
- 加权综合分
- tail exact words 对齐

阈值：

```text
FUZZY_SCORE_THRESHOLD = 0.88
FUZZY_EDIT_SIM_THRESHOLD = 0.84
FUZZY_BIGRAM_THRESHOLD = 0.45
FUZZY_CONTENT_OVERLAP_THRESHOLD = 0.70
FUZZY_MIN_SHARED_CONTENT_WORDS = 3
```

如果没有达到裁剪条件，但接近阈值，会打印 near-miss debug 信息，供后续调参。

release spec：

```text

```

```text

```

release build：


输出：

```text

```

debug build：

```bash
./scripts/build_macos_debug.sh
./dist/ClassroomTranscriberDebug/ClassroomTranscriberDebug
```

打包策略：

- 使用 PyInstaller onedir/windowed app bundle
- app 名称 `ClassroomTranscriber.app`
- bundle id `com.local.classroomtranscriber`
- 包含 `NSMicrophoneUsageDescription`
- 内置 `whisper-cli`
- 内置来自 `vendor/whisper.cpp/download-ggml-model.sh` 的版本锁定下载脚本
- 内置 `libwhisper` / `libggml` dylib
- 不内置 `ggml-large-v3.bin` 等模型
- 不把 settings/models/outputs 写进 app bundle

构建脚本会：

- 检测 Python、PyInstaller、PySide6
- 在运行 PyInstaller 前强制检查 Vendored 下载脚本存在、可读且 Shell 语法有效
- 清理旧 `build/` 和 `dist/`
- 运行 PyInstaller
- 修正部分 rpath
- ad-hoc codesign

PyInstaller 的下载脚本来源是主仓库 `vendor/whisper.cpp`，且缺失时构建明确失败。
`whisper-cli`、`libwhisper` 和 `libggml` 系列动态库仍来自构建机的
`external/whisper.cpp`。模型文件本身不参与打包。

## 13. Debug build 与 crash log

`crash_debug.py` 记录 frozen app 早期启动和退出日志。

日志路径：

```text

```

记录内容：

- app start
- frozen status
- `sys.executable`
- cwd
- Python version
- PySide6 / Qt version
- resource paths
- open main window
- start/stop recording
- closeEvent entered/completed
- QApplication aboutToQuit

- before sys.exit
- uncaught Python exception

曾经出现过 PySide6/Qt 在 frozen app 退出时的 `EXC_BAD_ACCESS`，栈落在 `QObject::~QObject()` / `QDialogWrapper` / `PySide::destroyQCoreApplication()`。当前通过显式 `safe_shutdown()`、dialog 引用管理、signal 断开、timer stop、stop thread join 修复。

## 15. 真实课堂实测结论

已实测路线：

```text
whisper.cpp + Metal + large-v3
```

课堂测试观察：

- CPU idle 长期基本大于 80%，偶尔到 60%+
- 内存大概 10-13.7 / 16GB 波动，基本绿色，偶尔棕色
- 10 分钟测试机身只是温，不烫
- raw / clean 都能正常写入
- 转写质量比早期 `turbo` baseline 更适合作为课堂实时输入

这些结论来自特定 MacBook Air 和真实课堂环境，其他机器仍需实测。

## 16. 已知技术债

- app 打包体积较大，当前 PyInstaller 构建会带入一些无关依赖。
- `whisper.cpp` 仍按 chunk 启动 CLI，存在进程启动开销。
- 没有正式签名和 notarization。
- 没有 universal2。
- 没有 Windows 打包。
- 没有 LLM cleanup / summary。
- 没有 OpenCC 等简繁体规范化。
- `stream_transcribe.py` 同时承担旧 CLI、backend helper、dedup helper，长期可拆分。
- settings 目前是简单 JSON，没有 schema migration。
- Model Manager 的下载依赖 curl/wget 或系统网络环境。
- `external/whisper.cpp` 是被忽略的本地源码和构建依赖，不应作为主项目源码提交；
  模型下载脚本已单独 Vendored，不再从 external 解析。

## 17. 后续优化路线

- 继续用真实课堂测试 Stop drain、queue backlog、长时间稳定性。

- 在 Model Manager 中显示下载进度和下载速度。

中期：

- 将 `whisper.cpp` CLI 调用替换为长驻 server 或 native binding。

- 增加更系统的课堂音频回放测试集。
- 改进 session 浏览和历史记录管理。

长期：

- notarization 和正式 release 流程。
- universal2 或单独 Intel build。
- Windows 平台独立评估。
- 离线 LLM cleanup / summary，作为转写后的独立模块，而不是实时主链路。
